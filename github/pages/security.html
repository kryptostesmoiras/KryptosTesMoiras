Security and AI

The project described in our documents, feature by feature.

AVAILABLE LOCALLYPLANNEDUNDECIDED

Statuses distinguish local prototype features from planned or undecided modules. Planned features are not enabled.

◇PLANNED

Hashes, not your source

AI has no direct access to hosted source. A separate analyzer produces hashes and filtered CST-derived artifacts. Raw CSTs may contain code and must not be transmitted unchanged.

Reference document Security.md
◎PLANNED

No training by default

Using AI must not train or update model weights with your projects. Any future training requires separate explicit consent. Context retention and caches must be minimized and verified.

Reference document Security.md
◈PLANNED

Sentinel stays independent

The planned supervisor checks service health and containment conditions using deterministic rules. AI must not disable it, expand its own permissions or erase audit evidence.

Reference document ReadMe.md
✓PLANNED

Approve the exact action

Planned sensitive operations require approval signed on a phone or separate device, bound to target, parameters and expiry, with replay protection. Private keys remain on that device.

Reference document ReadMe.md
↺PLANNED

Recover without stopping everything

Containment must be targeted and preserve Sentinel, logs and emergency access. Encrypted backups, restoration and lost-phone replacement must be defined and tested before operation. Administration and recovery interfaces must remain separate from the public interface.

Reference document ReadMe.md
▥PLANNED

Resources under control

CPU, memory and storage quotas must preserve supervision and recovery capacity. The proposed initial host has 64 GB of RAM: a design target, not a performance guarantee.

Reference document ReadMe.md
